# 1. 总体变化

V1.1 主要解决 V1.0 中的接口口径不一致问题，重点包括：

- 补齐关键结构体总表，避免 API 入参结构体在总览中缺失。
- 明确参数读取只返回参数值，不返回参数描述或 UI 分组元数据。
- 明确参数写入不自动触发回读校验，回读校验由上层显式调用。
- 明确终端自描述按内容片段回调，上层按 `request_id` 聚合。
- 为文件类异步结果补充“不支持”结果码。
- 明确安全 transport 与协议库重连职责边界。
- 修正运行期选项函数名为 `<prefix>_set_option`。
- 补充单点读取、主动上送与点表主路径边界说明。

# 2. 关键结构体总表补齐

| 变化项 | V1.0 | V1.1 | 影响 |
| --- | --- | --- | --- |
| 总召与电度量召唤请求 | 详细 API 使用对应请求结构体，但 3.5 总表未列出 | 新增 `iec_interrogation_request_t`、`iec_counter_interrogation_request_t` | 总览与详细定义一致 |
| 参数校验与定值区请求 | 详细 API 使用对应请求结构体，但 3.5 总表未列出 | 新增 `iec_parameter_verify_request_t`、`iec_setting_group_request_t` | 调用方更容易从总览定位请求模型 |
| 自描述请求 | 详细 API 使用 `iec_device_description_request_t`，总表未列出 | 新增 `iec_device_description_request_t` | 自描述请求和回调结构体区分更明确 |
| 校时请求 | `clock_sync` 使用 `iec_clock_sync_request_t`，总表未列出 | 新增 `iec_clock_sync_request_t` | 校时接口入参在总览中可见 |
| 原始 ASDU 发送请求 | `send_raw_asdu` 使用 `iec_raw_asdu_tx_t`，总表未列出 | 新增 `iec_raw_asdu_tx_t` | 旁路发送请求模型在总览中可见 |

# 3. 参数读取与参数描述边界

| 变化项 | V1.0 | V1.1 | 影响 |
| --- | --- | --- | --- |
| 参数读取模式 | 支持读取全部、按域、按分组、按地址范围 | 支持读取全部、按域、按地址范围；按 UI 分组需由上层转换为地址条件 | SDK 不直接承载 UI 分组读取语义 |
| 参数读取请求字段 | 包含分组名和返回描述信息开关 | 移除分组名和返回描述信息开关 | 参数读取请求更贴近协议参数值读取 |
| 参数读取回调 | 可返回参数值和参数描述 | 只返回参数值分帧结果，不承载描述或分组元数据 | UI 展示所需名称、单位、分组由上层自描述缓存补齐 |
| 参数描述结构体定位 | 表达参数元数据 | 表达上层从 XML/msg 自描述解析得到的缓存元数据 | 明确描述信息来源不是终端定值召唤回调 |

# 4. 参数写入与回读校验

| 变化项 | V1.0 | V1.1 | 影响 |
| --- | --- | --- | --- |
| 写后校验 | `verify_after_write` 表示写入成功后自动回读校验 | `verify_after_write` 保留且必须为 `0`，不触发自动校验 | 写入和校验职责拆开 |
| 写入回调 | 写入后可能触发 `on_parameter_indication` | 写入只触发 `on_parameter_result` | 回调路径更可预测 |
| 回读校验 | 可由写入接口隐式触发 | 上层在写入成功后显式调用 `<prefix>_verify_parameters` | 上层负责决定校验时机和范围 |
| 流程章节 | “参数写入与回读校验流程” | “参数写入与显式回读校验流程” | 示例代码同步改为先写入、再显式校验 |

# 5. 终端自描述返回方式

| 变化项 | V1.0 | V1.1 | 影响 |
| --- | --- | --- | --- |
| 自描述回调语义 | 表述为收到终端自描述内容，部分章节又提到分片 | 明确收到自描述内容片段 | 回调语义统一 |
| 聚合责任 | 倾向于库内部重组后交付完整内容 | 库按片段交付，上层按 `request_id` 聚合 | 上层需要拷贝片段并在 `is_complete != 0` 后解析 |
| `is_complete` 字段 | 表示是否已接收完整内容 | 表示当前片段是否为本次请求最后一片 | 字段语义更适合分片模型 |
| 流程示例 | 单次回调后触发解析 | 多片追加，最后一片触发解析 | 示例与结构体定义一致 |

# 6. 文件能力结果码

| 变化项 | V1.0 | V1.1 | 影响 |
| --- | --- | --- | --- |
| 文件异步不支持结果 | 文件结果码没有“不支持”枚举 | 新增 `IEC_FILE_RESULT_UNSUPPORTED = 10` | 文件目录、读写、取消等异步失败可明确表达协议或终端不支持 |
| 文件能力退化 | 只能用拒绝、协议错误等结果间接表达 | 可用同步 `IEC_STATUS_UNSUPPORTED` 或异步 `IEC_FILE_RESULT_UNSUPPORTED` | 三套库同形 API 的退化语义更清晰 |

# 7. 点值模型修订

| 变化项 | V1.0 | V1.1 | 影响 |
| --- | --- | --- | --- |
| 归一化遥测 | `iec_point_type_t` 支持归一化遥测，但 `iec_point_data_t` 缺少承载字段 | `iec_point_data_t` 新增 `int16_t normalized` | 点值类型和数据联合体一致 |
| 点表主路径 | 主要描述总召和点表回调 | 补充周期上送、变化遥测、变位遥信仍走 `on_point_indication` | 主动上送不依赖上层先发起总召 |
| 单点读取 | 口径较粗 | 补充 `C_RD_NA_1` 语义、适用场景和限制 | 避免把点值读取误用于参数、文件或点表配置读取 |

# 8. 安全 transport 与重连边界

| 变化项 | V1.0 | V1.1 | 影响 |
| --- | --- | --- | --- |
| 重连职责 | 协议库有重连事件和重连间隔，但安全状态恢复边界不够清楚 | 协议库只负责协议层重试和链路事件；真实资源重建、安全认证、密钥协商由 transport 或上层负责 | 避免协议库直接依赖安全接口库 |
| 安全断链处理 | 要求断链后重新认证，但未说明 SDK 重试时如何阻断业务帧 | 安全 transport 在重新认证和密钥协商完成前必须拒绝或阻塞业务明文 `send`/`recv` | 防止安全状态未恢复时继续业务交互 |
| 安全接口库 | 不直接调用安全库 | 进一步明确不得导出 `sec_*`、`SG_*` 等安全库包装接口 | SDK 边界更明确 |

# 9. 运行期选项命名

| 变化项 | V1.0 | V1.1 | 影响 |
| --- | --- | --- | --- |
| 运行期选项函数名 | 公共配置约束中写作 `iec_set_option` | 统一为 `<prefix>_set_option` | 与三套库同形导出函数一致 |

# 10. 对调用方的主要影响

- 调用方不能再把参数读取当作“参数值 + 描述元数据 + UI 分组”的混合通道。
- 若界面需要按分组展示或刷新参数，应先获取 XML/msg 自描述并在上层建立分组到地址条件的映射。
- 参数写入后如需校验，应显式调用 `<prefix>_verify_parameters`。
- 自描述内容回调必须按片段拷贝和聚合，不能假设单次回调就是完整 XML/msg 文件。
- 文件能力不支持时应优先识别 `IEC_FILE_RESULT_UNSUPPORTED` 或同步 `IEC_STATUS_UNSUPPORTED`。
- 安全接入时，transport 必须负责安全状态机和业务明文帧门控。
